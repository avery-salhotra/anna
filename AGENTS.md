# Repository instructions

- Run the complete available test suite after every change and fix failures
  caused by the change.
- Update `readme.md` and relevant project documentation after every change.
  Keep documentation grounded in behavior that is actually implemented and
  verified.
- Never claim that a test or check passed unless it was actually run
  successfully.

## Mandatory Engineering Apprenticeship

For every request that involves planning, designing, implementing, modifying,
debugging, reviewing, testing, or verifying software in this repository:

1. Read `.agents/skills/engineering-apprenticeship/SKILL.md` completely before
   taking action.
2. Apply the `engineering-apprenticeship` skill even when the user does not
   name it.
3. State in commentary that the skill is active and identify the current
   apprenticeship stage.
4. Follow the skill's human checkpoints before modifying implementation code.
5. Work on only one independently testable behavior at a time.
6. Do not bypass the workflow because the requested change appears simple.
   Scale the depth proportionately, but preserve human participation and
   independent verification.
7. Treat the human as the final technical owner.
8. Run all configured tests and update `readme.md` and relevant documentation
   after every change.
9. Never claim that a test or check passed unless it was actually run
   successfully.

This requirement is persistent for this repository and does not require a
keyword or explicit skill invocation from the user.

### Exceptions

Do not invoke the full apprenticeship workflow for:

- Purely conversational questions
- Status requests
- Reading or explaining existing code without proposing changes
- Simple repository navigation
- Requests explicitly limited to research with no implementation
- Urgent containment of destructive, security-sensitive, or
  production-impacting behavior

For an exception, still provide evidence-based reasoning and follow all
applicable repository instructions.
